## API and version workflow
Public HTML shell GET /manny, authenticated GET /dynamite/settings and POST /dynamite/settings/save, /activate, /restore. Existing MASTRA_API_TOKEN bearer authentication. All responses no-store; no server keys returned. UI connects using access token held only in page memory. No tokens in URLs or version rows.
Version = {id,label,settings,createdAt,hash}. GET = {active:Version,versions:Version[],baseline:Settings,photos:PhotoCard[],capabilities:{persistent:boolean,laya:string,memoryAvailable:boolean,hindsightAvailable:boolean,customerSendsEnabled:boolean,baselineIdentity:string}}. POST save {label,settings} -> {version}; save never activates. POST activate {versionId,expectedActiveId} -> {active}, atomic compare-and-set conflict409. POST restore {versionId,label?} -> {version}, creates a new inactive copy with all settings; then operator chooses Use this version. No version deletion.
Every model/instructions/tools/options/memory/scorer hook for one request must use the same pinned version, including webhook overrides. Native Studio and webhook use the same resolver. Photo enable/caption settings and example settings reach real tool/route boundaries. Approved photo assets remain unchanged; captions cannot replace an image or transfer its consent. Newly registered quotes store their followup plan; existing tasks retain their schedule. Active integration credentials stay server-side.

## States, failures and evidence
Disconnected -> connected -> editing -> saved draft -> active. Save/restore failure retains edited values and current active version. Conflict returns409 and requires refresh; no overwrite. Unavailable DB returns503 and UI explains changes are not saved; no fake success. Bad settings return400 with field errors. Unauthenticated401. No inference or provider changes occur during version writes. Request timeout keeps outcome unknown until state/history reread; repeat saves may create another immutable draft but cannot activate one accidentally.

## Private chat tester

Select any saved version, open **Test Manny**, type as a homeowner, and choose **Send to Manny**. Saving a draft is sufficient; activation is not required. Unsaved edits must first be saved or reset so the version shown is the version tested. Switching versions starts a fresh browser-only conversation. **New conversation** clears its history and image previews.

Authenticated POST `/dynamite/settings/chat` accepts `{versionId, history, message, conversationId}`. The server loads the immutable version itself, pins its photo settings, uses the exact Fireworks resource and generation options, and applies the existing reply rules. The response identifies model/version, tool calls, human handoff status, and any original approved photo selected. Images load through the existing authenticated preview route. Chat never activates a version.

This tests the saved prompt, generation settings, six tool toggles, and photo settings. CRM lookup returns a clearly identified private-test stub. No live CRM reads, customer sends, shared conversation-memory retrieval/writes, representative examples, Hindsight operations, follow-ups, or grading are invoked. Laya remains explicitly unverified. This is not full production parity.

The existing Fireworks key must be configured on the server and `MANNY_CHAT_ENABLED=true` enabled within an approved spending scope. Missing credentials or disabled chat returns 503 before inference. Invalid input returns 400; unknown saved versions return 404; sanitized provider failures return 502. The UI keeps a failed message for manual retry, never retries automatically, and warns that a timeout may still use credits. The flag is an operator activation setting, not a dollar-budget enforcement system. Private replies are limited to the 4,000-character history contract; any shortened reply is labeled in the conversation.
